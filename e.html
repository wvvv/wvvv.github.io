Overview

它解决了什么问题

验证码、业务通知、告警短信常常落在一张插在角落设备里的 SIM 卡上——人不在现场就看不着， 换卡查短信更是麻烦。SMS Forwarder 把这事儿做成一条自动流水线： 设备收短信 → 长连接上报 → 服务端匹配规则 → 多点触达。

📴

传统方式的痛点

SIM 卡插在异地设备里，收短信必须人到现场；短信分散在多张卡上难以归集； 无法与自动化流程打通；设备掉线无人知晓。

✅

SMS Forwarder 的做法

双卡常驻在线，短信到达即上报云端并秒级推送；支持关键词与黑名单过滤； 可转发到 9 种通道触发下游自动化；设备掉线主动告警。

Editions

两种运行模式，同一台硬件

设备是否连接服务器，是一个可以随时切换的开关。接上服务器就是「服务器版」， 关掉就是「纯本地版」——硬件完全相同，随时切换，不需要重新烧录。

Server Edition

服务器版 · 联网集中管理

设备通过加密长连接接入你自己部署的服务器，短信统一归档、多点分发、远程可控。

  • 短信全量入库，支持长期检索、未读标记与全部已读
  • Web 管理面板 + 微信小程序，不受局域网限制，随时随地查看
  • 单账号集中管理多台设备，可绑定 / 解绑 / 共享（控制 · 只读角色）
  • 设备掉线自动告警，恢复上线即时通知
  • 远程指令经服务器下发：重启、重初始化、飞行模式、测速、AT 指令
  • 支持账号密码 / 短信验证码 / 微信登录
适合：多台设备要统一管理、团队共用、需要出门在外查看历史短信、想用小程序接收。
Standalone Edition

纯本地版 · 单机独立运行

不接任何服务器。设备自己收短信、自己过滤、自己推送，短信留在设备里，不出局域网。

  • 设备直连第三方通道推送，不经过任何中间服务器
  • 可选邮件通知，设备直接投递到你的邮箱
  • 可选 MQTT 输出，接入 Home Assistant 等本地自动化平台
  • 浏览器打开设备内置网页即可查看短信、发短信、改配置
  • 本地保留最近 100 条短信，号码黑白名单与关键词过滤照常生效
  • 本地网页直接下发指令：发送短信、测速、重启、飞行模式
适合：只要把短信转出去、看重隐私不想让数据过服务器、单台设备自用、已有本地自动化平台。

Message Flow

一条短信是怎么走到你手上的

无论哪种模式，前半段完全相同：SIM 卡收到短信 → 设备解析并过滤。 区别只在过滤之后往哪儿送。 注意两种模式下，设备的推送通道、邮件、MQTT 都是由设备自己直连发出的，不依赖服务器。

服务器版

上行：短信 → 你

经过服务器
  1. SIM 卡收到短信模组唤醒主控，长短信自动拼接
  2. 设备本地过滤号码黑白名单 → 内容关键词，命中即拦截
  3. 加密长连接上报设备 → 服务器，秒级送达
  4. 服务器匹配规则并归档入库、标记未读、命中转发规则
  5. 实时下发到客户端Web 面板 · 微信小程序 · 未读角标
  6. 服务器侧通道分发 按你的配置转发到： 企业微信钉钉飞书TelegramBarkGotify自定义 Webhook
并行支路：同一条短信还会由设备同时直连发出——设备本地推送通道、邮件、MQTT。三路互不等待，任一链路故障不影响其余。
下行：指令怎么回设备
面板点「重启 / 测速 / 发短信」→ 服务器 → 加密长连接 → 设备执行 → 结果沿原路回传，终端实时打印。
纯本地版

上行：短信 → 你

不经过服务器
  1. SIM 卡收到短信模组唤醒主控，长短信自动拼接
  2. 设备本地过滤号码黑白名单 → 内容关键词，命中即拦截
  3. 写入设备本地短信库保留最近 100 条，浏览器随时翻
  4. 设备直连并发推送 三条路同时发出，全部由设备自己完成： 推送通道（9 种）邮件通知MQTT → Home Assistant
  5. 你在手机上收到通知Bark / Telegram / 企微 / 钉钉 / 飞书 / Gotify 任选
  6. 浏览器直连设备查看打开 http://sms.local 或设备局域网 IP，无需账号服务器
数据边界：短信正文只留在设备里，只有你主动配置的推送目标会收到内容——没有中间服务器，也没有第三方经手。
下行：指令怎么下发
设备内置网页点「发短信 / 测速 / 重启 / 飞行模式」→ 设备就地执行，整条链路不出局域网。

FAQ

常见问题

服务器版和纯本地版该怎么选？差别到底在哪？

核心区别只有一条：设备过不过服务器。接服务器能换来长期归档、随时随地访问、微信小程序、多台设备集中管理和掉线告警；不接服务器则短信不出局域网，设备自己直连推送通道，隐私性最好、部署最省事。如果你只是想把验证码转出来，纯本地版就够了；如果要团队共用、要在外面翻历史短信，选服务器版。两种模式共用同一台硬件，随时切换。

纯本地版没有公网服务器，出门在外还能收到短信吗？

能。推送通道是设备通过自己的 4G 网络直接发出去的，走的是 SIM 卡的移动数据，跟家里局域网无关——Bark、Telegram、企业微信、钉钉、飞书、Gotify、自定义 Webhook 都能照常收到。纯本地版少了的只是「远程打开面板翻历史短信」，历史记录要在局域网内打开设备网页查看，或者直接用手机上的推送通知。

短信内容会不会被第三方看到？

纯本地版下，短信只停在设备里，只有你主动配置的推送目标会收到内容，没有任何中间服务器。服务器版下，短信经过你自己部署的服务器——服务端与数据库都在你手里，不经过任何第三方平台。无论哪种模式，推送通道都只在你命中转发规则时才向外发送。

两种模式可以同时用吗？

可以。设备接上服务器的同时，本地配置的推送通道、邮件和 MQTT 依然会并行发出——这几条路互不等待、互不干扰。所以你既能享受面板的多端管理与归档，又能保留一条不依赖服务器的直连推送作为兜底。

设备需要一直插着 SIM 卡吗？

是的。设备的作用就是把插在其中的 SIM 卡短信转发出去，SIM 卡需保持插好且模组在线。两张卡槽相互独立，插一张也能正常工作。

推送会有明显延迟吗？

设备与服务端之间保持长连接，短信到达后由设备主动上报、服务端即时下发，端到端通常在 1 秒内完成，实际耗时主要取决于运营商网络与模组响应。

一台设备可以给多个人用吗？

可以。设备所有者可开启分享并设置名额，其他用户输入设备编码绑定后即可访问，并可分配「控制」或「只读」角色；所有者随时可解绑或清除全部绑定。

短信数据存在哪里，安全吗？

整套方案为自托管部署，服务端与数据库都由你自己掌控，短信记录不会经过任何第三方平台。推送通道仅在命中转发规则时按你的配置向外发送。

设备掉线了能发现吗？

可以。服务端持续监测设备心跳，掉线超过阈值会向绑定用户推送离线提醒；恢复上线同样会即时通知。你也可以在面板随时查看心跳时间与在线状态。

模组卡死了怎么办？软件重启不管用呢？

可以直接对问题卡槽做硬件级断电重启：设备切断该模组供电，稍作延时后重新上电，相当于手动拔插一次电源，比指令软重启彻底得多。操作只针对指定卡槽，另一张卡不受影响。

能对单个卡槽单独开关机吗？

可以。每个模块都能独立启用 / 禁用与切换飞行模式，两张卡互不干扰——维护或停用其中一张时，另一张仍可持续接收短信。也可以单独对某一个模块执行断电重启，而不必整机重启。

Ping 测速的目标地址可以改吗？

不需要在面板手动指定。目标由服务端统一配置，日常使用点一下即可；如需调整（例如换成国内 DNS），在服务端改一次便对所有设备生效。面板展示的结果就是设备实际 Ping 的目标地址。
